## summary
MySQL中的索引也叫Key,用于快速找到记录的一种数据结构,类似通过书的目录查找内容一样,不一样的是数据库可以插入数据,修改数据,索引也需要更改,所以当
数据量超大,维护索引的成本也许会很高

## 单列or多列
索引可以包含单列也可以包含多列的值,如果是多列那么列的顺序很重要,MySQL只能使用最左前缀匹配.创建两个单列索引和创建一个两列的索引不同的

## 索引类型
a.B-Tree索引(记录有序),对硬盘友好的数据结构,每个节点页尽可能多包含叶子页,在保证查找效率的情况下减少硬盘访问次数.使用B-Tree索引查找要遵循从最左列开始查找
b.Hash索引(记录无序),精确匹配查找,不支持部分匹配查找,但速度更快,但索引中没有存储数据不能使用覆盖索引查询

## 聚簇索引
a.聚簇索引并不是一种索引类型,而是一种数据存储方式,在InnoDB中是在同一个结构中保存了B-Tree索引和数据行,因为数据和索引放在一起所以叫聚簇,因为数据不同同时放在
两个不同的地方,所以一个表只能有一个聚簇索引.

b.默认主键作为聚簇索引,没有主键则找一个唯一非空索引替代,如果都不存在则隐式定义一个主键来作为聚簇索引

c.二级索引,给InnoDB表其它列建立索引叫二级索引,索引值不是指向数据行的指针,而是指向对应的主键列,好处是插入数据页分裂不用去维护二级索引的指针


## 在InnoDB中按主键索引插入行
如果主键没有顺序,则插入会造成很多页分裂,更加浪费空间和页分裂开销

## explain查看select查询计划
type: system < const < eq_ref < ref < ... < index(扫描全部索引) < all(全表扫表)
rows: 扫描表的行数

## mysql实现乐观锁
采用一个version值,update  tableName set version=version+1 where id=#{id} and version=#{version}
并发修改innodb会使用行锁,避免并发修改
