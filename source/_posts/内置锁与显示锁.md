## 简介
在多线程编程,为了控制对共享数据的访问或者线程之间协作工作,需要用到锁,锁的类型:  
- 内置锁
- 显示锁

内置锁:java中使用关键字synchronized修饰的方法或代码块,jvm会自动加锁或解锁,如果没有获取到对象锁那么当前线程  
将会被挂起,当拥有该对象锁的线程释放锁的时候,在该对象锁上挂起的线程将会被调度,这一切都是jvm自动完成  

显示锁:在代码中显示的获取锁和释放锁,相当将内置锁中jvm自动完成的功能用代码来完成  

## 内置锁与显示锁的区别  
显示锁比内置锁更加灵活,内置锁获取不到就会被挂起,直到拥有锁的线程释放锁才有机会再次运行.而显示锁可以采用轮询,  
去检查是否可以获取到锁,或者可定时,还可以使用可中断的等待获取锁,所以显示锁更加灵活  

## 锁与线程间通信
java采用共享内存实现线程间通信,线程通过访问锁来实现通信. 

## 内置锁实现
java中每个对象都拥有一个monitor对象,所以每个对象都可以来用作锁,获取锁时,查看monitor是否被其它线程持有,
如果被其它线程持有则将当前线程加入monitor的wait set中,如果没有被其它线程持有则设置当前线程为monitor的持有者  

## 显示锁实现
显示锁和内置锁实现方式类似,只是用编码的方式来实现了查看锁状态,以及实现锁的等待队列,而且显示锁中查看锁如果被其它  
线程持有,那么可以选择是否挂起当前线程,更加灵活  

## ReetrantLock
java中该类实现显示锁,标准用法如下:
~~~
 public void m() {
      lock.lock();  // block until condition holds
      try {
        // ... method body
      } finally {
        lock.unlock()
      }
    }
~~~
在使用显示锁时需要在finally块中释放锁,防止代码抛出异常导致锁没有被释放,内置锁synchronized方法,  
编译器会在字节码中自动生成异常处理表用来释放锁,不用手写释放锁的代码  

## ReetrantLock实现
在JUC包中,很多并发数据结构同步都采用AbstractQueuedSynchronizer.简称AQS,该类具有内置锁的所有功能行为  
AQS中包含同步状态字段state,等待队列.

### lock.lock()分析:  
~~~
 final void lock() {
            if (compareAndSetState(0, 1))
                setExclusiveOwnerThread(Thread.currentThread());
            else
                acquire(1);
        }
~~~  
1.首先compareAndSet(0,1)来设置state,如果成功则成功获取锁,state状态设置为1,然后返回,否则执行下一步
~~~
    public final void acquire(int arg) {
        if (!tryAcquire(arg) &&
            acquireQueued(addWaiter(Node.EXCLUSIVE), arg))
            selfInterrupt();
    }
~~~
2.acquire,先执行tryAcquire没有成功返回false,然后创建等待节点,并将等待借点假如wait queue,调用LockSupport.lock  
将当前线程挂起  

~~~
    public final boolean release(int arg) {
        if (tryRelease(arg)) {
            Node h = head;
            if (h != null && h.waitStatus != 0)
                unparkSuccessor(h);
            return true;
        }
        return false;
    }
~~~
3.当执行lock.unlock();在同步器sync上执行release(1),修改state状态为0,然后使用AQS提供的unparkSuccessor泛起  
队列中的一个线程,使用LockSupport.unpark(thread);让被挂起的线程被jvm重新调度  

### lock.trylock()分析
直接检查AQS state状态,如果为0表示没有被其它线程获取,那么获取成功,否则返会获取锁失败  

### lock.tryLock(long timeout, TimeUnit unit)分析
有等待时间的trylock使用LockSupport.parkNanos(this, nanosTimeout);把当前线程挂起指定时间.先查询是否可以获取锁  
没有获取到然后在等待指定时间  


## ReetrantLock的公平与非公平
显示锁获取锁分为公平(fair)和非公平(nonfair)  
公平:请求获取锁时,检查如果有其它线程已经在排队了,那么当前线程加入排队中  
非公平:请求获取锁时,直接访问AQS state的状态,如果没有其它线程暂用,那么直接获取锁,如同插队  

非公平的锁策略效率高是因为不用去检查有没有线程在排队,显示锁默认非公平策略
