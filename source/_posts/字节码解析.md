解析class文件要点:
1.常量池位置0不存储,例如常量池有15个item, 则constant_pool_count=16, 常量池索引从1开始

2.u1,u2,u4都是无符号类型,不要和java的byte,short,int对应, 可以自定义类型U1,U2,U4

3.attribute属性根据attribute_name_index指向常量池的值来确定具体是什么属性,然后进入
具体的属性,比如Code,确定了属性类型,然后根据Code_attribute结构定义再解析字节码
因为在attribute_info中已经知道attribute_name_index和attribute_length
所以在具体的属性中对应着两个值是知道的,解析时class不在重复,所以应该跳过这两个值,不要再次读取这两个值

4.解析常量池,常量池中数据类型的tag已知,比如constant_utf8_info中tag为1,不应再从class中读取

5.使用DataInput读取应调用readUnsignedXxx(),int除外,int最大值2G,字节码不可能会超过这个值,所以读取U4不会有问题

6.code_attribute用于存储字节码

7.解析字节码,可以分析有哪些方法,不用使用类加载器加载,然后再使用反射分析.比如要加载包名和类名
都相同的一个类,只要知道他们的区别,通过字节码分析就可以确定,当然使用asm分析类不用字节维护解析器

## 实例方法赋值

	public class A {
    	private int x;
    	private void test(){
        	this.x = 55555555;
    	}
	}

	 stack=2, locals=1, args_size=1
    0: aload_0							//把this压栈 ..., objectref →
    1: ldc           #2                  // int 55555555  常量池constant_integer_info存储55555555  ..., objectref, 55555555 →
    3: putfield      #3                  // Field x:I  设置this.x=55555555
    6: return

## 方法调用

	public class A {
    private int x;
    private void test(){
        this.x = 55555555;
        int xx = s(6);
        System.out.println(xx);
    }

    private int s(int z){
    return z;
    }
	}

	      stack=2, locals=2, args_size=1
         0: aload_0
         1: ldc           #2                  // int 55555555
         3: putfield      #3                  // Field x:I
         6: aload_0
         7: bipush        6
         9: invokespecial #4                  // Method s:(I)I
        12: istore_1
        13: getstatic     #5                  // Field java/lang/System.out:Ljava/io/PrintStream;
        16: iload_1
        17: invokevirtual #6                  // Method java/io/PrintStream.println:(I)V
        20: return

	调用先将参数压栈,然后invokespecial(私有,构造,接口方法,父类方法), 调用方法返回后,如果有返回值,则返回值在方法调用者的operand上.
	
	方法调用invokespecial #XX 会根据后面的参数XX索引,在常量池中找到对应方法,MethodRef然后确定类和方法,但是这里还没有到具体的MethodInfo,
	对于实例方法可以通过this引用指向的class,找到对应的MethodInfo执行code

	invokespecial和invokevirtual指令之间的差异是：invokevirtual指令用于调用象所属的类中定义的方法，而invokespecial指令用于调用实例初始化方法（§2.9）、private方法和当前类的超类中的方法。在JDK 1.0.2之前，invokespecial指令曾被命名为invokenonvirtual。
